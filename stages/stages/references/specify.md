# Specify

Use this stage to resolve intended outcomes and externally meaningful obligations. Read the request, applicable governance and domain context, related targets, and relevant current behavior.

Distinguish required behavior, optional behavior, assumptions, and unresolved product choices. Keep operational values flexible where the user designates them operational. Record terminology and accepted intent through `project-documentation`, using existing owners rather than imposing a specification file.

A user-directed or jointly agreed target needs no duplicate approval. An agent-proposed material target change requires direction before adoption.

The boundary is enough accepted intent and clear acceptance conditions for the next authorized work, with consequential open questions explicit. Proceed to Plan when approach or verification decisions need separate work. For a small change with a sufficiently clear approach, Specify may lead directly to Implement within the assignment and project rules. Neither a planning stage nor a separate planning artifact is mandatory merely because specification work occurred.
