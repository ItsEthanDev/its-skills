# Agent constitution guidance

Read the [constitution](../../CONSTITUTION.md) and relevant project context
before proposing or changing governed work. The constitution owns the principles,
scope, approval authority, and amendment procedure.

## Apply or amend constraints

Distinguish accepted constraints from current implementation and feature-specific
requirements. Ask about unresolved consequential choices; do not infer policy
from existing artifacts or promote a one-feature requirement into governance.

Use existing policy owners rather than introduce competing sources.
For proposed principles, state an actionable rule and an observable compliance
signal. Surface conflicts with accepted governance before proceeding.

Follow the constitution's approval procedure. An agent's proposal does not change
accepted governance. Keep agent-specific operating methods in agent guidance;
keep shared project constraints in their canonical project documents.

## Reconcile and verify

Reconcile directly affected specifications, plans, instructions, and checks.
Verify changed paths, links, and commands at their sources.

Report governance changes, unresolved decisions, and verification results.
Establishing governance does not authorize further development.

## Maintenance

Changes to this procedure require explicit project-maintainer approval.
Constitutional changes follow the constitution's governance rules.
Keep this guide's links and the README documentation index current.
