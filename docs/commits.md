# Commit guidance

Consult this guide before committing project changes.

## Prerequisites

Complete the applicable [quickstart verification](quickstart.md#verify-a-change)
and review changed work against the constitution and applicable project guidance.
No separate review ceremony is required.

Reuse completed checks and reviews when their results still cover the changes.
If a required prerequisite is blocked, report the blocker and do not commit
until it is resolved.

## Message format

Use a concise imperative subject stating the purpose of the change.
Conventional Commits prefixes are not required. Add a body when the rationale
or constraints need explanation.

Do not infer a competing convention from incidental commit history.

## Reporting

Report the commit hash and subject, or the exact reason the commit failed.

## Branches and publication

This guide adds no branch restrictions. Follow applicable repository protections
and explicit instructions.

A request to commit does not imply permission to push. Before an authorized
push, verify the branch, remote, and consequential effects described in
[distribution guidance](deployment.md). Surface conflicting instructions rather
than treating this guide as an override.

## Maintenance

Changes require explicit project-maintainer approval. Record approved changes
here and reconcile affected project instructions.
