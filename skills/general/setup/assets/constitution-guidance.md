# Agent constitution guidance

Read the [project constitution](../../CONSTITUTION.md) and relevant project context before proposing or changing governed work. The constitution owns the principles, scope, approval authority, and amendment procedure; this guide explains how to apply and maintain it.

## Establish or amend constraints

Distinguish accepted constraints from current implementation and feature-specific requirements. Ask about unresolved consequential choices; do not infer policy from code or promote a one-feature requirement into governance.

Use existing policy owners. Propose a consolidated constitution only when the project needs one and has none; do not introduce a competing owner for an accepted rule.

Record accepted, actionable rules and an observable compliance signal. Obtain direction before adopting agent-proposed policy. If a proposed change conflicts with governance, surface the conflict rather than bypassing it.

Follow the constitution's ratification and amendment procedure. An agent's proposal does not change accepted governance. Do not duplicate approval rules here; follow their canonical owner.

Keep agent-specific operating instructions in the applicable agent entry point. Point to canonical human-facing documentation for shared facts.

## Reconcile and verify

Reconcile directly affected specifications, plans, instructions, and checks. Verify changed paths, links, and commands at their sources.

Return the governance changes, unresolved decisions, and verification results. Stay within the assignment; establishing governance does not authorize further development.

## Maintenance

Keep this guide's constitution link and the documentation index current when locations change. Changes to this procedure follow <the project's agreed approval process>; changes to the constitution follow its own governance rules.
