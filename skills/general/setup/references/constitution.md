# Constitution

Establish a constitution when the user wants a consolidated owner for durable project constraints. Preserve existing governance and policy owners. A scoped request can establish or amend a constitution without setting up the rest of the project.

Ask what bounds the user already has in mind. Distinguish accepted constraints from current implementation and feature-specific requirements. A small constitution with a few agreed rules is useful; do not invent principles to fill the template or create an empty claim of authority.

Use the constitution seed for the human-facing purpose, scope, principles, compliance signals, and governance. Confirm who approves amendments, how ratification is recorded, and which dependent documents and checks must be reconciled. Preserve an existing amendment process and obtain its required approval before changing governance.

Use the agent constitution guidance seed for the operating method: consult existing governance, distinguish durable rules from implementation choices, propose rather than infer policy, surface conflicts, and reconcile and verify affected work. Keep this method in the agent guide, not in the constitution's human-facing introduction. Link to the actual constitution; its approval authority and amendment rules remain canonical there.

Replace every retained placeholder before ratification. Make draft versus ratified status explicit; an agent's proposal is not adopted policy. Establish the maintainer or approval role rather than assigning that authority to the agent.

Link the constitution under Project documentation and its agent guide under Agent documentation. Add a direct consultation trigger in the harness-loaded instruction file. The generated project must contain the method and approval procedure rather than depend on an installed skill.

A later setup run can propose migration, but follows the existing ratification procedure rather than overwriting it.
