# Quickstart

Get from a fresh checkout or project directory to the first useful local result. Preserve working instructions and link to their authoritative owner rather than duplicating them.

The quickstart needs prerequisites, configuration, exact commands, and expected results. Use the project's actual tools and workflow: opening a writing workspace, rendering a paper, running a local application, or performing a learning activity need different instructions. A project without a server does not need startup instructions for one.

Document required tools, access, dependency installation, configuration sources, and any background services that really are needed. Document secret names and how to obtain access, never secret values. State whether changing configuration also requires action in a deployed environment; point to deployment guidance when that workflow exists.

Include the checks appropriate to the project and what passing looks like. For an engineering project that may include build, lint, formatting, and tests; for prose it may include document rendering, link checks, or source checks. Don't invent a check that has not been established.

Use the quickstart seed template as a starting point. Remove sections that don't apply. Run safe local commands when feasible; distinguish instructions verified by execution from those only inspected or still unresolved.
