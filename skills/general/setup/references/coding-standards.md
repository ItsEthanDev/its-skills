# Coding standards

Establish a discoverable owner for the project's coding standards when the user expects to use one. Preserve an existing standards document or external guide rather than introducing a competing owner.

Ask whether the user has standards they want to add, or an existing guide they want to follow. Record agreed project conventions, not assumptions inferred from whatever code happens to exist. The document can start with a few rules, or an explicit statement that no additional project-specific standards have been agreed yet. Its purpose and maintenance instructions still belong there.

Use the coding-standards seed template. Establish when contributors consult it, how user-approved standards are recorded, and how conflicts are raised. A proposed standard does not become policy merely because an agent notices a pattern. Don't require agents to create every possible policy document later; the user can request scoped setup when one is needed.

Keep tool-enforced lint and formatting rules in the selected tool configuration. The standards document can link to that owner and explain project-specific judgment calls; it should not maintain another copy of the ruleset. Setting up standards does not also select or install a toolchain unless that feature is in scope.
