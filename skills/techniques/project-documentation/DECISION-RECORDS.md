# Decision Records

Use an ADR for a consequential technical or domain-boundary tradeoff that would be hard to reverse and surprising to a future maintainer without its rationale. Otherwise let the plan, code, or domain context own the decision. Follow the repository's established location; otherwise use `docs/adr/<short-title>.md`, adding a stable number when the repository's convention calls for one.

State the context, chosen approach, and reason, with links to affected owners. An ADR preserves the decision's rationale, not a parallel feature requirement or an exception to governance unless governance expressly allows one. If the decision changes, keep the historical ADR intelligible and link the new decision; living feature specs should instead describe only the current target. The [ADR starter](templates/adr.md) is optional.
