# Qualitative evaluation

1. **Define observable criteria.** Identify whose work should improve and select representative tasks, including difficult cases and counterexamples. State what makes each criterion better, worse, or inconclusive. Separate constraints from preferences and resolve consequential competing priorities. Use concrete observations, not aesthetic preference or invented scores.
2. **Compare actual artifacts.** Apply the same tasks and context to both artifacts. Cite passages, dependencies, execution paths, or task outcomes. Separate observations from judgments; identify advantages, regressions, costs, and unknowns. If the claim concerns user or agent behavior, observe that behavior or narrow the claim. Clearer wording alone does not prove fewer mistakes.
3. **Use a separate evaluator when feasible.** Launch a fresh read-only subagent with the criteria, cases, constraints, and both artifacts, without the author's preferred verdict. Use neutral labels and conceal which is newer when practical. Require evidence, not merely a winner. If resources or permissions prevent this, disclose the limitation and have the supervisor compare directly. The author's self-assessment is insufficient; acceptance remains with the supervisor.

Examples of evidence include missing steps in an operational guide, leaked invariants in an interface, or contradictions in a proposal. Distinguish artifact findings from predicted benefits: a hypothetical maintenance task reveals design pressure, not measured future savings.

Report qualitative judgments separately from measurements. Do not combine unlike criteria into an unsupported overall score.
