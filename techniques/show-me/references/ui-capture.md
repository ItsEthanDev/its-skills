# UI capture

Capture the requested UI for visual feedback. Screenshots show appearance at one moment. They do not prove interactive behavior; report interaction checks separately if performed.

1. Identify the requested app, route, and UI state, including relevant data, tab, dialog, or scroll position. Use an explicit desktop viewport of **1440x900 CSS pixels** unless the user requests another size. Keep this default even when the user will view the image on a phone; the viewing device does not select mobile emulation. Resolve missing inputs that would change the requested screen before capture.
2. Inspect the project's available browser tooling and reuse it, such as an existing Playwright setup. Use the project's established app startup procedure and browser configuration. Do not introduce dependencies or a new capture framework implicitly. If the available tools cannot capture the target, report the limitation and ask how to proceed.
3. For authenticated pages, use a dedicated authorized test account or an explicitly authorized protected session. Do not bypass authentication. Keep credentials, cookies, storage state, browser profiles, and other session artifacts outside Git. Use non-sensitive test data when possible, and keep sensitive screenshots in protected storage outside Git with delivery restricted to the authorized audience. If access or private handling is unavailable, stop and request direction.
4. Navigate to the requested route and establish the intended state. Wait for the relevant UI to be ready and for fonts and required images to load before capturing. Use observable readiness conditions rather than treating a completed navigation or fixed delay as sufficient. Capture the viewport by default. Add a full-page image when requested or needed to show content outside the viewport, and label it as full-page rather than substituting it silently.
5. Open and inspect the actual captured image with an image-capable tool. Confirm that it shows the requested route and state, not an unintended login, error, or loading screen. Check for missing content or fonts and clipped areas that obscure the requested UI. Correct and recapture mismatches. If image inspection is unavailable, report that the capture is unverified rather than claiming success.
6. Deliver the inspected image in chat if the channel supports images, or through an existing authorized private gallery reachable from the user's phone. Label each image with its route, viewport dimensions, UI state, and viewport or full-page scope. Check that the attachment is present or that the gallery image loads through the authorized access path; report any unverified device access. A local file path alone is not proof that the user can see the image. If neither delivery option is available, ask for an authorized destination. Do not upload publicly, create a new gallery, expose a service, or change network or Tailscale configuration without explicit permission.

Complete the capture only when the image has been inspected, labeled, and delivered through an accessible authorized surface. State any remaining capture or access limitation instead of presenting an inaccessible artifact as delivered.
